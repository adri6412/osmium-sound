# assets/

Placeholder for desktop-app packaging icons (`icon.png` 512×512 for Linux,
`icon.icns` for macOS, `icon.ico` for Windows). Today the directory is empty
and nothing reads it: the `build` block in `package.json` sets no icon, so the
Electron build CI still runs (`electron-builder --linux dir`, needed only
because `distro/build-distro.sh` requires `--app-dir`) uses Electron's default
icon. The on-screen interface the appliance actually shows is the Qt one
(`native-ui-qt/`), which draws fullscreen straight to the display and has no
window icon, so none is shipped.

Brand imagery actually used by the product lives elsewhere:

- `logo osmium.png` (repo root) — the product logo: README header image and
  Plymouth boot-splash logo, copied into the ISO by `distro/build-distro.sh`
  (as the theme's `logo.png`). Fielded devices get the splash logo from the OS
  payload, `distro/os-update/files/logo.png`.
- `native-ui-qt/icons/` and `native-ui-qt/assets/` (VU meter skins, status
  plate) — images of the Qt on-screen interface, copied into `/opt/hifi-qt` by
  `native-ui-qt/ci/build-payload.sh`.
- `src/assets/` — images bundled into the legacy Electron renderer; the Qt
  payload also takes its boot intro from here (`src/assets/intro.mp4`, turned
  into frames by `build-payload.sh`).
- `distro/config/includes.binary/{isolinux,boot/grub}/splash.png` — ISO boot
  menu background, generated by `build-distro.sh`.
- `flasher/assets/` — Osmium Flasher's icon and the OTA public key it verifies
  images with.

To create icons from a single source image with ImageMagick:

```bash
convert source.png -resize 512x512 icon.png
convert icon.png -define icon:auto-resize=256,128,96,64,48,32,16 icon.ico
# .icns needs macOS `iconutil` or https://github.com/actaeon/icns-tools
```

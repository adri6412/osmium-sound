Osmium Sound — Private Beta Privacy Notice

Last updated: 17 August 2026 · Applies only to devices running a private beta / dev-channel build

Scope of this notice: this page describes data collection that runs only on appliances installed from this /beta page or otherwise switched to the Dev/Alpha OTA channel, for the duration of the private beta test. Stable production releases (the main download on osmiumsound.it) do not currently run this feature. Once the private beta ends, this data-collection feature and all data already collected through it will be removed/deleted.

1. Data controller

Adriano Frongillo, sole developer of Osmium Sound.
Contact: support@osmiumsound.it

2. What is collected

A background agent (hifi-beta-agent) runs on the appliance for the duration of the private beta and sends the following to our server (telemetry.osmiumsound.it) over HTTPS:

a) Periodic device snapshot

Sent automatically (by default every 10 minutes; we can remotely change this interval for the whole beta fleet):

FieldExample
Hostname / device labela name given to the device
Appliance software versionv2.5.21-dev.104
CPU model, core count, CPU load %, temperatureIntel N100, 4 cores, 12%, 48.2°C
GPU model and GPU busy %Intel UHD, 6%
RAM total/used, disk total/used8192 MB / 3100 MB
Network connection type and local IP addresswired, 192.168.1.42

b) Diagnostic network captures (HAR)

Only during short capture windows that we schedule remotely (this is not continuous, and there is currently no on-device switch to trigger or block it yourself), the appliance records the network requests made by its own on-screen interface — not system-wide network traffic, and not requests from any other device on your network. Authentication and session information (streaming-service logins, cookies, API tokens, and any header matching a token/secret/session pattern) is automatically stripped before the capture file is even written, so it never leaves the device. Response bodies are also never captured — no page content, images or audio. What remains is request/response URLs, HTTP method, status codes, and timing; URLs can still include things like track/album identifiers or search terms typed into the interface. Access to these captures is restricted to the data controller.

c) Performance captures

During the same capture windows, CPU and memory usage per interface screen/tab is logged, to help diagnose slowdowns.

d) Device identifier

A technical identifier derived from the appliance's machine ID, plus an access token used only to authenticate uploads from that specific device. Neither is tied to your name unless you chose to put your name in the device's hostname/label.

3. Why we collect it

Solely to find and fix bugs and performance problems, and improve the software during the private beta. It is never used for advertising or profiling, and is not sold or shared with third parties.

4. Legal basis

Consent (Art. 6(1)(a) GDPR), given by choosing to install and run a beta/dev-channel build after being informed by the notice on the download page and this document.

5. Who can access it

Only the data controller, through a password-protected dashboard. Processors involved purely for hosting: Oracle Cloud, which hosts telemetry.osmiumsound.it (receives the data described above), and Cloudflare Pages / GitHub (host this website and the software downloads, and do not receive appliance telemetry).

6. Retention

Captures are deleted from your device automatically right after a successful upload — nothing accumulates on the appliance itself. On the server, data is kept only for the duration of the private beta. When the beta ends, this feature is switched off and the data collected through it is deleted.

No in-app opt-out yet. During the beta there is no Settings toggle to disable this data collection on a device that is already running it, and switching to a different OTA channel does not remove the agent already installed. The only way to guarantee no data is shared is to not install a beta/dev-channel build in the first place — or, if you already have, to wipe the device and not run Osmium Sound again for the rest of the private beta. The first production release after the private beta ends will ship an update that removes the data collector entirely.

7. Your rights

Under GDPR you can, at any time, contact us at support@osmiumsound.it to:

  • ask whether we hold data about your device, and get a copy of it;
  • withdraw your consent (equivalent to switching the device off the Dev/Alpha channel or uninstalling the beta);
  • receive it in a portable format.

To identify your device for one of these requests, tell us its hostname/label or approximate registration date.

8. Security

All uploads are made over HTTPS. The dashboard used to view this data is protected by a password known only to the data controller. No third-party advertising or analytics SDKs are involved in this data collection.

9. Changes

This notice may be updated as the beta evolves; check the date at the top. Material changes will also be reflected on the beta download page.

Osmium Sound — Informativa Privacy Beta Privata

Ultimo aggiornamento: 17 agosto 2026 · Si applica solo ai dispositivi con una build della beta privata / canale dev

Ambito di questa informativa: questa pagina descrive la raccolta dati che gira solo sui dispositivi installati da questa pagina /beta o comunque passati al canale OTA Dev/Alpha, per la durata della beta privata. Le versioni stabili di produzione (il download principale su osmiumsound.it) al momento non eseguono questa funzione. Al termine della beta privata, questa funzione di raccolta dati e tutti i dati già raccolti tramite essa verranno rimossi/eliminati.

1. Titolare del trattamento

Adriano Frongillo, unico sviluppatore di Osmium Sound.
Contatto: support@osmiumsound.it

2. Cosa viene raccolto

Un agente in background (hifi-beta-agent) gira sul dispositivo per la durata della beta privata e invia quanto segue al nostro server (telemetry.osmiumsound.it) via HTTPS:

a) Snapshot periodico del dispositivo

Inviato automaticamente (di default ogni 10 minuti; possiamo cambiare questo intervallo da remoto per l'intera flotta beta):

CampoEsempio
Hostname / etichetta dispositivoun nome dato al dispositivo

Tipo di connessione di rete e indirizzo IP localecablata, 192.168.1.42

b) Catture diagnostiche di rete (HAR)

Solo durante brevi finestre di cattura che attiviamo da remoto (non è continuo, e al momento non esiste un interruttore sul dispositivo per attivarlo o bloccarlo autonomamente), il dispositivo registra le richieste di rete effettuate dalla sua interfaccia a schermo — non il traffico dell'intero dispositivo, e non le richieste di altri dispositivi sulla tua rete. Le informazioni di autenticazione e sessione (login dei servizi di streaming, cookie, token API e qualsiasi header che corrisponda a un pattern token/secret/session) vengono rimosse automaticamente prima ancora che il file di cattura venga scritto, quindi non lasciano mai il dispositivo. I corpi delle risposte non vengono mai catturati — nessun contenuto di pagina, immagine o audio. Quello che resta sono URL di richiesta/risposta, metodo HTTP, codici di stato e tempistiche; gli URL possono comunque includere elementi come identificativi di brani/album o termini di ricerca digitati nell'interfaccia. L'accesso a queste catture è riservato al titolare del trattamento.

c) Catture di performance

Durante le stesse finestre di cattura, viene registrato l'utilizzo di CPU e memoria per ogni schermata/tab dell'interfaccia, per aiutarci a diagnosticare rallentamenti.

d) Identificativo del dispositivo

Un identificativo tecnico derivato dal machine ID del dispositivo, più un token di accesso usato solo per autenticare i caricamenti da quel dispositivo specifico. Nessuno dei due è collegato al tuo nome, a meno che tu non abbia scelto di inserire il tuo nome nell'hostname/etichetta del dispositivo.

3. Perché lo raccogliamo

Esclusivamente per trovare e correggere bug e problemi di performance, e migliorare il software durante la beta privata. Non viene mai usato per pubblicità o profilazione, né venduto o condiviso con terze parti.

4. Base giuridica

Consenso (art. 6(1)(a) GDPR), dato scegliendo di installare ed eseguire una build beta/canale dev dopo essere stati informati tramite l'avviso nella pagina di download e questo documento.

5. Chi può accedervi

Solo il titolare del trattamento, tramite una dashboard protetta da password. Fornitori coinvolti puramente per l'hosting: Oracle Cloud, che ospita telemetry.osmiumsound.it (riceve i dati sopra descritti), e Cloudflare Pages / GitHub (ospitano questo sito e i download del software, e non ricevono la telemetria del dispositivo).

6. Conservazione

Le catture vengono eliminate automaticamente dal dispositivo subito dopo un caricamento riuscito — nulla si accumula sul dispositivo stesso. Sul server, i dati vengono conservati solo per la durata della beta privata. Al termine della beta, questa funzione viene disattivata e i dati raccolti tramite essa vengono eliminati.

Nessuna disattivazione in-app per ora. Durante la beta non esiste un interruttore nelle Impostazioni per disattivare questa raccolta dati su un dispositivo che la sta già eseguendo, e cambiare canale OTA non rimuove l'agente già installato. L'unico modo per avere la certezza di non condividere alcun dato è non installare affatto una build beta/canale dev — oppure, se l'hai già fatto, formattare il dispositivo e non usare più Osmium Sound per il resto della beta privata. La prima release di produzione successiva alla fine della beta privata includerà un aggiornamento che rimuove del tutto il collettore dei dati.

7. I tuoi diritti

Ai sensi del GDPR puoi, in qualsiasi momento, scriverci a support@osmiumsound.it per:

  • chiedere se conserviamo dati relativi al tuo dispositivo, e ottenerne una copia;
  • revocare il consenso (equivalente a riportare il dispositivo fuori dal canale Dev/Alpha o disinstallare la beta);
  • riceverli in un formato portabile.

Per identificare il tuo dispositivo ai fini di una di queste richieste, indicaci il suo hostname/etichetta o la data approssimativa di registrazione.

8. Sicurezza

Tutti i caricamenti avvengono via HTTPS. La dashboard usata per consultare questi dati è protetta da una password nota solo al titolare del trattamento. Nessun SDK pubblicitario o di analytics di terze parti è coinvolto in questa raccolta dati.

9. Modifiche

Questa informativa può essere aggiornata con l'evolversi della beta; controlla la data in alto. Le modifiche rilevanti saranno riportate anche nella pagina di download della beta.
